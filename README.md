# agentbox

Ubuntu 26.04 LTS Incus VM for [Hermes Agent](https://hermes-agent.nousresearch.com/).
It runs a vanilla Xfce desktop on X11 so Hermes can drive a real, visible
Google Chrome over CDP and use cua-driver for computer use without Wayland
workarounds or a GPU.

The VM is provisioned by [`cloud-init/user-data.yaml`](cloud-init/user-data.yaml)
and the chezmoi source in [`dotfiles/`](dotfiles/), which the VM pulls from
this repository.

## What is installed

| Component | Source | Notes |
| --- | --- | --- |
| Xfce on X11, LightDM | apt (`xubuntu-core`) | Autologin for `agent` (UID 1000, passwordless sudo) |
| GNOME Keyring | apt | `login` keyring with an empty password, so autologin never prompts |
| Google Chrome | Google apt repository | `hermes-browser.service`, CDP on `127.0.0.1:9222` |
| 1Password, `op` | 1Password apt repository | Sign in manually |
| Tailscale | Tailscale apt repository | Joined with `just tailscale-up` |
| xrdp + x11vnc | apt | RDP on `:3389` shows the live autologin desktop |
| Hermes Agent | upstream installer | Latest stable; `hermes update` owns upgrades; manages its own cua-driver |
| Hermes WebUI | GitHub, latest release | `hermes-webui.service` on `127.0.0.1:8787` |
| OpenChamber, OpenCode | npm, Homebrew | `openchamber.service` on `0.0.0.0:3000` |
| Traefik | Homebrew | `traefik.service` on `:443`, Cloudflare DNS-01 certificates |

User services:

| Unit | Purpose |
| --- | --- |
| `hermes-gateway.service` | Messaging platforms, cron, API server on `127.0.0.1:8642`; generated by `hermes gateway install` |
| `hermes-serve.service` | Dashboard / remote backend on `127.0.0.1:9119` |
| `hermes-webui.service` | WebUI; requires `~/.config/hermes/webui.env` |
| `hermes-browser.service` | Visible Chrome with a dedicated CDP profile in `~/.hermes/chrome-cdp` |
| `x11vnc.service` | Loopback VNC server on the X11 display, used by xrdp |
| `traefik.service` | Requires `~/.config/traefik/traefik.env` |
| `openchamber.service` | Requires `~/.config/openchamber/startup.env` |
| `personal-graph.service` | Requires `~/graph` |

Traefik routes (`dotfiles/dot_config/traefik/dynamic/`), all pointing at the
VM's Tailscale address in Cloudflare DNS:

- `hermes.<base_domain>` → WebUI
- `hermes-gateway.<base_domain>` → dashboard, `/gw` → gateway API server
- `graph.<base_domain>` → personal graph, tailnet only

## Provisioning

The defaults target the `jarvis:` Incus remote; override them with the
`AGENTBOX_*` variables at the top of the [`Justfile`](Justfile).

```sh
just create        # create the VM with cloud-init user-data
just wait          # wait for cloud-init, its reboot, and the X11 session
TS_AUTHKEY=tskey-... just tailscale-up
just status
```

cloud-init installs the desktop and third-party apt repositories, creates
`agent`, installs Homebrew and chezmoi, and runs
`chezmoi init --apply https://github.com/xtruder/agentbox.git` before rebooting
into the autologin session. chezmoi's scripts install Hermes, the WebUI and
OpenChamber, generate local passwords, and enable the user services.

To apply later changes to this repository inside the VM:

```sh
just shell
chezmoi update
```

### Incus 7.5.1 reboot loop

Incus 7.5.1's agent reboots a cloud-init guest before telling the host that it
applied the image templates, so the host re-applies them on every boot and the
VM never finishes booting. `just create` clears `volatile.apply_template` right
after the first start to avoid this. The bug is fixed upstream by
[lxc/incus@4e799f7287](https://github.com/lxc/incus/commit/4e799f7287); the
workaround can be removed once the host runs a release containing it.

## Secrets and local state

Nothing secret is stored in this repository. After provisioning, these files
live only in the VM:

| File | Contents | Origin |
| --- | --- | --- |
| `~/.hermes/.env`, `config.yaml`, `auth.json`, `mcp-tokens/` | Hermes credentials and configuration | Migrated or `hermes setup` |
| `~/.config/hermes/webui.env` | `HERMES_WEBUI_PASSWORD` | Generated on first apply |
| `~/.config/x11vnc/password` | RDP/VNC password (8 characters, a VNC limit) | Generated on first apply |
| `~/.config/traefik/traefik.env`, `acme.json` | `CF_DNS_API_TOKEN`, certificates | Copy from `traefik.env.example` |
| `~/.config/openchamber/startup.env` | `OPENCHAMBER_UI_PASSWORD`, `OPENCHAMBER_LAN_URL` | Created manually |

The WebUI, Traefik and OpenChamber units do not start until their files exist,
so a fresh VM never serves these apps without authentication.

## Remote desktop

Connect an RDP client to the VM's Tailscale address on port 3389 and enter the
password from `~/.config/x11vnc/password`. xrdp proxies to x11vnc on the
autologin display, so you see the same desktop that Hermes automates rather
than a second session.

## Browser automation

`hermes-browser` runs the system Google Chrome visibly with:

- a dedicated `--user-data-dir`, because Chrome 136+ ignores
  `--remote-debugging-port` on the default profile;
- CDP bound to `127.0.0.1:9222`, used by Hermes through `browser.cdp_url`;
- `--disable-blink-features=AutomationControlled` and no `--enable-automation`,
  so `navigator.webdriver` is `false`;
- SwiftShader WebGL, because the VM has no GPU and pages without WebGL are
  easier to fingerprint.

`~/.config/environment.d/50-agentbox.conf` sets `DISPLAY=:0` and
`XAUTHORITY` for all user services, so the gateway and WebUI can use computer
use even when they start before the desktop session.
